# 基米斗 / PussiFight — NDS 项目设计规格

日期：2026-08-23

## 1. 产品目标

《基米斗》（英文名 `PussiFight`，工程标识 `JiMiDoo`）是一款运行在 Nintendo DS 上的单人实时点击战斗游戏。玩家和电脑 AI 各控制一只愤怒的猫，通过观察对手状态、积攒怒气和及时哈气反制取得胜利。

游戏支持下屏触摸和实体按键。首版语言为简体中文和英文。

## 2. 技术路线

项目使用 BlocksDS 和 Wonderful Toolchain：

- ARM9 运行场景、战斗、AI、进度、存档、渲染和输入逻辑。
- ARM7 使用 BlocksDS 预编译的 `arm7_maxmod.elf`，负责音频和系统服务。
- 上屏使用 GL2D 绘制猫咪纹理、特效和程序动画。
- 下屏使用 2D 图层绘制状态栏、按钮和触摸区域。
- 构建系统使用 BlocksDS Makefile。
- 大型图像、字库和流式音乐存入 NitroFS，不嵌入 ARM9 ELF。
- 战斗规则独立于渲染，能够由主机端测试程序直接验证。

目标输出文件为 `PussiFight.nds`。

## 4. 猫种基础属性

所有猫默认可用，不包含解锁条件。

| 猫种 | 生命 | 基础攻击 | 老吴叫攒怒 | 回血速度 | 怒气上限 | 行动 CD |
|---|---:|---:|---:|---:|---:|---:|
| 橘猫 | 60 | 15 | +5/0.5 秒 | +15/秒 | 100 | 2 秒 |
| 狸花猫 | 65 | 16 | +5/0.5 秒 | +12/秒 | 100 | 2 秒 |
| 耄耋 | 70 | 10 | +5/0.5 秒 | +15/秒 | 75 | 2 秒 |
| 丑橘 | 60 | 10 | +10/0.5 秒 | +12/秒 | 100 | 2 秒 |
| 香蕉猫 | 60 | 15 | +5/0.5 秒 | +15/秒 | 100 | 1.5 秒 |

玩家五种猫分别拥有独立的地位和永久增益记录。

## 5. 战斗状态

每只猫持有：

- 当前生命和最大生命
- 当前怒气和怒气上限
- 全局行动 CD
- 僵直剩余时间
- 当前持续行动
- 闪避率
- 危险预知率

可行动条件为全局 CD 和僵直时间都归零。CD、僵直、预警和持续效果全部使用整数帧计时。

战斗开始时双方恢复最大生命，怒气归零。上一场的临时状态不带入下一场。

## 6. 怒气规则

怒气会一直保留，只有被成功哈气打断或反制时清零。主动结束老吴叫、使用其他行动、被普通抓挠命中和战斗中的时间流逝都不会消耗怒气。

抓挠伤害为：

```text
基础攻击 + floor(当前怒气 / 10) × 2
```

AI 对玩家抓挠的普通立即反制率为：

```text
max(40% - 玩家当前怒气 × 3%, 0%)
```

## 7. 四种行动

### 7.1 抓挠

抓挠是唯一直接造成伤害的行动。

玩家发起抓挠时：

1. AI 按普通立即反制公式判定哈气。
2. 反制成功时取消抓挠，玩家怒气清零并僵直 2 秒，不造成伤害。
3. 未被反制时判定目标闪避。
4. 闪避成功时完全免伤，且不打断目标正在进行的老吴叫或回血。
5. 命中时结算伤害，并中断目标的老吴叫或回血，但不清空目标怒气。

AI 发起抓挠时：

1. 按玩家危险预知率判定是否显示感叹号。
2. 出现预警时等待 0.7 秒。
3. 玩家在窗口内按 `L` 或触摸哈气，100% 反制抓挠。
4. 反制成功时 AI 怒气清零、僵直 2 秒，玩家哈气不进入 CD。
5. 没有预警的抓挠立即结算，不能进行临时反制。

基础危险预知率为 30%。

### 7.2 哈气

- 对正在老吴叫或回血的目标，成功率为 80%。
- 对处于预警阶段的 AI 抓挠，及时哈气成功率为 100%。
- 成功后打断行动、清空目标怒气并令目标僵直 2 秒。
- 成功哈气不启动自己的全局 CD，可以立即继续行动。
- 没有有效目标或判定失败时，正常启动全局行动 CD。

### 7.3 老吴叫

- 使用后立即启动全局行动 CD。
- 每 0.5 秒按猫种属性增加怒气。
- 达到怒气上限后停止增长，但仍保持老吴叫状态。
- 自己执行下一行动、被抓挠命中或被哈气成功打断时结束。
- 只有哈气成功打断会清空怒气。

### 7.4 嚼口香糖

- 使用后立即启动全局行动 CD。
- 每 1 秒按猫种属性恢复生命，不超过最大生命。
- 自己执行下一行动、被抓挠命中或被哈气成功打断时结束。
- 哈气成功打断会额外清空怒气并造成 2 秒僵直。

### 7.5 时间和输入

- 僵直期间全局 CD 继续倒计时。
- 只有 CD 和僵直都结束后才能行动。
- CD 期间不缓存行动输入。
- 任一方生命降到 0 时立即结束战斗，不处理该帧后续行动。
- `START` 暂停战斗；暂停时所有战斗计时停止。

## 8. 战斗输入与下屏布局

所有行动同时支持实体键和触摸：

| 实体键 | 行动 |
|---|---|
| L | 哈气 |
| R | 抓挠 |
| Y | 老吴叫 |
| A | 嚼口香糖 |

下屏上方约三分之一左右分栏：左侧显示己方血量和怒气，右侧显示敌方血量和怒气。下方约三分之二放置四个等大的触摸行动按钮。

CD 中的按钮变暗并显示剩余时间遮罩；僵直时四个按钮统一锁定；成功哈气后按钮立即恢复。

上屏只显示双方猫咪、动作演出、伤害数字、闪避、状态图标和感叹号预警，避免重复堆放详细数值。

## 9. AI 与危机等级

普通敌人的猫种随机选择。选定危机等级后生成敌人；退出战前情报再返回不会刷新，完成战斗或改选其他危机才重新生成。

危机等级 `E` 对普通敌人的基础强化为：

```text
最大生命 = 基础生命 × (100 + 2E)%
基础攻击 = 基础攻击 × (100 + E)%
行动 CD  = max(基础CD - floor(E/5) × 0.03秒, 0.7秒)
攒怒速度 = 基础值 + floor(E/20)
回血速度 = 基础值 + floor(E/20) × 2
```

所有计算使用整数或定点数，最终战前界面显示实际值。

AI 在每次可行动时为四种行动评分：

- 目标生命越低、自身怒气越高，抓挠分数越高。
- 玩家正在老吴叫或回血时，哈气分数显著提高。
- 自身怒气低且生命安全时，老吴叫分数提高。
- 自身生命比例越低，回血分数越高；满血时禁止回血。

危机等级提高选择最高分行动的概率：

- 1–24：偏随机。
- 25–74：识别基础回血和打断时机。
- 75–149：考虑双方怒气、预计伤害和致死线。
- 150–224：主动压制玩家持续行动。
- 225–255：大部分时间选择高分行动，但至少保留 15% 随机性。

普通危机成长不降低 30% 的基础预警率，也不绕过既定哈气公式。

## 10. 地位与挑战范围

玩家当前地位为 `P`。可选择的危机等级范围是 `P+1` 到下一个 5 的倍数，最高为 255。不能跳过下一个特化节点。

例如地位 11 时可以选择危机 12、13、14 或 15；危机 15 是固定特化敌人。

地位达到 255 后视为登顶。玩家仍可重复挑战危机 255 的最终特化敌人；胜利后地位保持 255，并按同级胜利规则获得 1 次增益选择。这样在地位封顶后仍可继续游玩和叠加未达到安全边界的增益。

胜利后：

```text
增益选择次数 = max(敌方危机 E - 胜利前地位 P, 0) + 1
新地位 = E
```

## 11. 特化敌人

每 5 级设置一个固定特化节点，共 51 个节点。节点预先指定猫种、模板和修正值，可以被记忆和针对。

首版复用约八种核心模板：

- 狂爪：强化攻击和 CD，削弱生命与回血。
- 铁壁：强化生命和回血，削弱攻击与 CD。
- 怒吼：强化攒怒和怒气上限，削弱基础攻击。
- 反制：强化哈气倾向和反制率，削弱生命。
- 闪避：强化闪避，削弱生命和回血。
- 嚼糖：强化回血，削弱攒怒和攻击。
- 先知：降低自身抓挠暴露预警的概率，削弱其他属性。
- 混合型：高等级节点组合两个模板，同时保留明显弱点。

特化模板可以修改通常固定的参数，但战前必须完整显示：最终属性、强化项、削弱项、反制率变化和预警变化。

## 12. 永久增益

每次增益机会展示三个不同类型。选择后立即更新层数，再抽取下一组。

某项增益的抽取权重为：

```text
基础权重 / (当前强化层数 + 1)
```

| 增益 | 每层效果 |
|---|---:|
| 强壮 | 最大生命 +5 |
| 凶猛 | 基础攻击 +1 |
| 敏捷 | 全局行动 CD -0.05 秒 |
| 大嗓门 | 每 0.5 秒攒怒 +1 |
| 口香糖专家 | 每秒回血 +2 |
| 闪避 | 闪避率 +2% |
| 危险预知 | 抓挠预警概率 +5% |
| 怒气容量 | 怒气上限 +5 |

增益效果固定，不做收益递减。安全边界为：

- 闪避最高 80%。
- 行动 CD 最低 0.5 秒。
- 危险预知最高 100%。
- 达到边界的项目退出候选池。
- 其他增益可无限叠加，但层数越高越难抽到。

## 13. 死亡与存档

当前猫死亡时：

- 地位归零。
- 八类永久增益全部清空。
- 只影响当前猫，不影响其他四只猫。
- 重置结果立即写入存档。

项目使用一个带版本号的二进制存档，包含：

- 五只猫各自的地位和增益层数。
- 当前语言和音量等全局设置。
- 文件魔数、格式版本和 CRC 校验。

保存时先写临时文件，再替换正式文件，并保留上一版备份。主文件损坏时尝试恢复备份。优先使用 flashcart DLDI 或 DSi SD 的可写文件系统；无法写入时允许继续游玩，但持续显示无法保存提示。

## 14. 场景流程

```text
启动并读取存档
→ 标题画面
→ 主菜单
   ├─ 开始游戏
   ├─ 战斗规则
   ├─ 设置
   └─ 制作人员
→ 选择玩家猫
→ 选择危机等级
→ 战前情报
→ 实时战斗
   ├─ 胜利：完成全部增益选择 → 保存 → 返回挑战选择
   └─ 死亡：清空当前猫成长 → 保存 → 返回猫咪选择
```

## 15. 本地化

首版支持简体中文和英文。`include/game_terms.h` 定义稳定的文本 ID，语言表分别位于：

```text
source/localization/strings_zh_cn.c
source/localization/strings_en.c
```

界面使用 `textGet(GameTextId id)` 获取文字。猫种、行动、增益、特化敌人、状态、菜单、规则、教程和错误提示都必须进入字符串表。

建议英文名词：

| 中文 | 英文 |
|---|---|
| 基米斗 | PussiFight |
| 橘猫 | Orange Cat |
| 狸花猫 | Tabby Cat |
| 耄耋 | Maodie |
| 丑橘 | Chouju |
| 香蕉猫 | Banana Cat |
| 哈气 | Hiss |
| 抓挠 | Scratch |
| 老吴叫 | Laowu Yowl |

语言可在设置中即时切换。存档只保存语言编号。构建工具从两份字符串表生成所需字符清单，中文字体只包含实际使用的汉字。

## 16. 猫咪图像素材

素材源模板为：

```text
https://www.bilibilitoy.com/toy/YmMvNRJDNp6gRKsk/24126970560512-v8847/Image/cat_x_y.png
```

角色映射：

```text
a 橘猫    b 狸花猫    c 丑橘    d 耄耋    e 香蕉猫
```

动作映射：

```text
1 老吴叫  2 哈气  3 抓挠  4 受击  5 回血  6 死亡  7 待机
```

素材保持写实抠图风格。每个行动使用一张静态图，通过程序位移、震动、闪白、残影、缩放和粒子形成动画。

处理流程：

1. 保存原始 RGBA 文件。
2. 去除透明空白并统一角色视觉比例。
3. 居中放入 128×128 透明画布。
4. 缩小锐化并清理白边。
5. 转换为适合 NDS 的 256 色纹理。

进入战斗前载入双方 14 张动作纹理。战斗中不读取图片文件。敌方通过水平翻转显示，不保存镜像副本。

## 17. 音频

现有 `Audios` 文件夹包含菜单音乐、战斗音乐、开始音效、通用动作音效以及耄耋和香蕉猫的特殊音效。

- 菜单音乐和战斗背景音乐循环播放并在场景切换时淡入淡出。
- `开始游戏音效.mp3` 用于确认进入战斗。
- `老吴叫.mp3` 用于老吴叫；普通哈气可将同一采样作为短促单次播放。
- 普通抓挠在 `抓挠.mp3` 和 `抓挠2.mp3` 间随机切换。
- 普通回血和死亡使用对应通用文件。
- 耄耋的哈气和抓挠都完整播放 `耄耋哈气+抓挠.mp3`。
- 香蕉猫使用专属攻击、回血和死亡音效。

BlocksDS/Maxmod 不直接使用 MP3。短音效转换为 Maxmod 可用的采样并加入 soundbank；两首长音乐转换为适合 NDS 的单声道低采样率流式格式，并从 NitroFS 播放。

本机已验证可用的转换工具为：

```text
C:\Desktop\格式工厂_v5.15.0_x64\格式工厂_v5.15.0.0_x64\ffmpeg.exe
```

构建辅助脚本通过可覆盖的 `FFMPEG` 路径调用它，不把该外部程序复制进仓库，也不在核心 Makefile 中强制绑定本机绝对路径。

- 短音效转换为 16000 Hz、单声道、8-bit PCM WAV，再由 `mmutil -d` 打包进 Maxmod soundbank。当前全部短音效转换后预计约 300 KB。
- 菜单音乐和战斗音乐转换为 22050 Hz、单声道、16-bit PCM WAV，保存在 NitroFS 中，通过 Maxmod 环形缓冲区流式播放。
- 流式音乐仍包含在最终 `.nds` ROM 内，玩家无需额外复制文件，但不会整体载入主 RAM。
- 不将两首背景音乐加入内存 soundbank；按当前时长估算，转换后的两首 16-bit WAV 合计约 6.8 MB，不适合普通 NDS 的 4 MB 主内存。

音频初始化失败时游戏以静音模式继续运行。

## 18. 性能约束

- 战斗使用固定帧更新。
- 主循环不进行动态内存分配。
- 战斗逻辑不使用浮点数。
- 纹理和音频在进入战斗前加载。
- 大型资源不嵌入 ARM9 ELF。
- 文件读取不发生在时间敏感的战斗帧中。
- 以 256×192 实际显示效果为验收标准。

## 19. 验证计划

主机端规则测试覆盖：

- 伤害与怒气加成。
- 普通反制公式。
- 80% 和 100% 哈气判定。
- 0.7 秒预警窗口。
- CD、僵直和持续行动中断。
- 闪避免伤且不中断持续行动。
- 地位跳升和挑战范围。
- 增益权重与安全边界。
- 死亡只重置当前猫。

存档和本地化测试覆盖：

- CRC 损坏检测和备份恢复。
- 旧版本存档迁移。
- 五只猫记录隔离。
- 两种语言的文本 ID 完整对应。
- 字库包含全部实际字符。

NDS 运行验证覆盖：

- melonDS 完整流程。
- 触摸与实体键同步输入。
- 音频循环、淡入淡出和场景切换。
- 文件读取、存档失败和静音降级。
- 真实 NDS/DSi 上的帧率、触摸精度、纹理辨识度和存档。

## 20. 完成标准

首版完成需要满足：

- 五只猫均可选择并拥有独立成长存档。
- 1–255 危机等级和 51 个固定特化节点可正常挑战。
- 四种行动、AI、反制、预警、闪避和持续效果按本规格结算。
- 胜利增益、地位跳升和死亡清空逻辑完整。
- 中英文可切换且无缺字。
- 35 张猫咪动作素材和现有音频全部正确接入。
- ROM 能在 melonDS 和真实硬件运行并保存进度。
